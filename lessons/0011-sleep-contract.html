Make sleeping tasks ineligible

Goal: implement tick-based sleep using the context switch you already built. You write the implementation; bring each part to chat for review before building.

State and time

Keep saved_sp first in the task record: assembly stores through offset zero. Add READY/SLEEPING state and a uint32_t remaining-tick count. Use a countdown for this first version, rather than an absolute wake timestamp, to avoid timestamp rollover comparisons. An optional global tick count is for observation only.

Each SysTick decrements positive counts of sleeping application tasks once, marks zero-count tasks ready, then requests PendSV. Never decrement zero. Tick sleep counts future tick interrupts, not a guaranteed number of full tick periods. See FreeRTOS tick resolution.

Selection and idle

Preserve round robin among ready A/B tasks. If only one is ready, keep selecting it. If neither is ready, select an independently stacked idle task that loops forever and never sleeps. From idle choose ready A before ready B. Idle is a fallback, not a third equal participant. Initialize all records before enabling the timer.

Atomic publication

An interrupt must not observe a half-updated sleep request. A critical section temporarily masks configurable interrupts. PRIMASK records that mask: MRS reads it, CPSID i sets it, MSR restores the saved value. Masking covers state/count updates and the PendSV request. Restore the prior mask afterward; pending PendSV then becomes eligible. Never wait for a switch with interrupts masked. Volatile alone does not make multiple operations atomic. First API contract: privileged Thread mode, interrupts initially enabled, no ISR callers.

task_sleep(n) publishes a countdown and sleeping state for n greater than zero, then pends PendSV using the same ICSR write as SysTick. For n equal to zero, only request a yield. Do not call schedule_next directly from a task, because that changes ownership before the outgoing context is saved. Sleep returns normally when its task resumes. Keep save/select/restore in PendSV. See Arm Cortex-M3 guide: MRS/MSR/CPS, PRIMASK, ICSR, and exceptions.

Implementation order

  1. Task fields and readiness-aware selection; review.
  2. Idle stack, record, entry and initialization; review.
  3. Tick countdown helper called from SysTick; review assembly call preservation.
  4. Sleep API and protected publication; review.
  5. Rebuild yourself, then test with GDB.

Calling C from SysTick with BL overwrites live LR. Preserve exception-return LR and keep MSP eight-byte aligned at the C call boundary. Hardware has already saved interrupted r0–r3/r12; a normal C helper preserves r4–r11. Do not copy a BL into the current return-only handler without handling LR.

Acceptance checks

  • Only A sleeping: B continues.
  • Both sleeping: idle runs and ticks continue.
  • Count 3 becomes 2, 1, 0 over three ticks; task becomes ready at zero.
  • Zero delay yields without sleeping.
  • Resumed task continues after sleep with its counter retained.

Becoming ready permits selection; it does not guarantee execution at that instant. Primary reading: FreeRTOS vTaskDelay. Ask followup questions in chat whenever a mechanism is unclear.
