Pause a task without losing its work

Your boot and global-initialization observations are complete. Today’s small win: explain one failure that a task switch must prevent. This is the first step toward switching tasks in your own RTOS.

The state you already know

Registers hold working values. The program counter (PC) identifies execution position; the stack pointer (SP) identifies the current stack position. See the Arm Cortex-M3 guide, §2.1.3, Core registers. For this exercise, assume both tasks use the same CPU.

Predict one instruction

Task A pauses just before this instruction:

adds r2, r0, r1

At the pause, A has r0 = 10 and r1 = 20. Task B runs and leaves r0 = 100 and r1 = 200. Our deliberately incomplete switch returns to A’s correct instruction, but leaves B’s values in those two registers.
