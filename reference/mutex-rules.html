TINYRTOS REFERENCE

Mutex ownership

  • A mutex is free or has exactly one task as its owner.
  • Ownership persists across task switches.
  • A successful acquisition grants the current task exclusive access. Every caller that uses the resource follows the same mutex protocol.
  • Only the owner can release the mutex.
  • In the first TinyRTOS version, try_lock returns false immediately whenever the mutex is held.
  • Protect each ownership check and update together. Restore the previous interrupt mask before returning.

Blocking acquire in TinyRTOS

  • The mutex records one waiter. The scheduler skips the waiter while it is blocked.
  • A successful unlock clears ownership and makes the waiter ready.
  • The waiter retries when scheduled. Its lock call succeeds once it becomes the owner.
