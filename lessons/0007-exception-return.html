Return through a saved frame

Goal: explain where the CPU gets the resume address after the RTOS selects a task's context.

On exception entry, Cortex-M3 puts a special EXC_RETURN value in the handler's LR. This differs from an ordinary function return address. In Handler mode, a return instruction such as bx lr with a valid EXC_RETURN value triggers hardware exception return. Source: Arm guide, §2.3.7, Exception return.

For our tasks running in Thread mode with PSP, 0xFFFFFFFD means return to Thread mode using the hardware frame located through PSP. Hardware restores that frame, including the saved PC and xPSR. This value identifies return mode and stack selection; it does not identify task B by name.

Before this return, our RTOS must already have restored B's software-saved r4–r11 and set PSP to B's hardware frame. Setting LR alone is not a complete context switch.

One prediction

Assume we are in Handler mode, B's software registers are restored, PSP points to B's valid hardware frame, and LR contains 0xFFFFFFFD. The handler executes bx lr.
