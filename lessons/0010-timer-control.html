Regain control

Goal: locate the vector that will let a timer interrupt your running task. This is the first step toward switching tasks without requiring SVC.

Your cooperative kernel reaches its scheduler when a task yields. If A keeps running without yielding, B cannot resume. SysTick can request an exception periodically; enabling it and scheduling from that exception are separate steps. See Arm Cortex-M3 Devices Generic User Guide, §§2.3 and 4.4.

Preserve the interrupted task

If A is interrupted, its live state must be preserved before restoring B. Hardware stacks r0–r3, r12, LR, PC, and xPSR; your software saves r4–r11. B's previously saved context remains on B's stack. Review task state and task and handler stacks.

One small investigation

Arm assigns SysTick exception number 15. Each vector-table word is four bytes, and the initial stack-pointer word occupies index 0. In startup.S, count from that first word: which existing entry occupies index 15?

Share the entry in chat for feedback before editing or enabling the timer. Next we will give that entry its own handler, then configure and observe the timer in separate steps. Run builds yourself when we reach that checkpoint.

Recall question: if A has r4 = 42 before the interrupt, why must the kernel save A's registers before allowing B to run? Ask your teacher followup questions whenever a step is unclear.
