TINYRTOS · 14

Your first printk

Get one boot message from TinyRTOS onto your terminal. That gives you a visible checkpoint between reset and the first task launch.

Follow one byte

printk is a kernel function that turns a message into bytes and hands those bytes to an output device. The device for this lab is a UART, a peripheral that sends bytes over a serial connection. As with your SysTick registers, the CPU controls it by accessing fixed memory addresses. QEMU emulates the UART and can send its output to the terminal.

For example, the letter B in a boot message goes through the string writer to a one-byte UART transmit operation, then through QEMU to the host terminal. The string writer can later gain formatting, and the UART code can be swapped for an STM32 implementation during the hardware port.

Implement one boot message

  1. Initialize the device. Use the first CMSDK UART on QEMU mps2-an385. Find the base address in QEMU’s board source and identify the transmit enable, baud divisor, status, and data registers in its UART model.
  2. Send one byte. A polling transmitter repeatedly reads the device status until the UART has room. Implement a byte output function using that contract. Test it with a visible character before adding the string writer.
  3. Send a string. Give version one the interface void printk(const char *message). Send the bytes in order and stop at the terminating zero byte. Print TinyRTOS boot followed by a newline once in main(), after UART initialization and before svc #0 launches the first task.

Add each new C source to the kernel.elf target in rtos/CMakeLists.txt. From rtos/, configure once for a new build directory, then build.

cmake -S . -B build -DCMAKE_TOOLCHAIN_FILE=cmake/arm-none-eabi.cmake
cmake --build build

From the same directory, run the rebuilt ELF with the first serial port connected to your terminal. -display none disables the graphical window and -monitor none leaves standard input and output available for the serial connection.

qemu-system-arm -M mps2-an385 -kernel build/kernel.elf \
  -display none -monitor none -serial stdio

Done when the single-character test works, then the boot line appears once per launch with no missing characters. The first version has one caller before scheduling starts. Formatting and concurrent callers are later exercises.

Before you run it, predict what your byte function does while the transmit buffer is full. Then share your prediction and the terminal output so we can compare them. Ask me if a register or part of the output path is unclear.
