A mutex that waits

In your last demo, each task slept after unlocking to give the other a chance to acquire the mutex. While A held it, B could still burn CPU time retrying. A blocking mutex lets B set its attempt aside. The mutex records B as a waiter, and the scheduler skips B until an unlock makes it eligible to run again. Zephyr mutex concepts

Reuse the wake-and-retry pattern from your semaphore. A blocked B stays inside its original lock call. A's unlock clears the owner and wakes B. When B next runs, it checks whether the mutex is free and claims it if it can. This keeps the check that grants ownership in one place.

Predict the wakeup

A owns the mutex and sleeps for a few ticks. B calls the blocking acquire. At the instant A later unlocks, who owns the mutex, what is B's state, and has B's call returned?

Check your prediction

The owner is empty, B is ready, and B's call is still in progress. The call can return success after B runs and records itself as owner.

Implementation contract

Use the existing two tasks and one statically allocated mutex with at most one waiter. Call the blocking acquire from task context with interrupts enabled on entry.

  • State. Track the owner and waiter in the mutex. Track mutex waiting in the task record. Initialize the mutex with both pointers empty and initialize the mutex wait state of each task as ready. Update task_schedule_next() so a task waiting on the mutex is ineligible to run.
  • Acquire. Keep the immediate operation as mut_try_lock(). Give mut_lock() blocking behavior when another task owns the mutex. Return false immediately if the caller already owns it. If the caller must wait, record it as the waiter, mark it blocked, and request a switch. When the call resumes, retry the acquisition. Return true only after recording the caller as owner.
  • Release. Keep the owner check. A successful unlock clears ownership, clears any recorded waiter, and makes that waiter ready. The waiter gets another chance to acquire when the scheduler runs it.
  • Interrupt mask. Protect the check and waiter registration together so an unlock cannot slip between them. Protect the owner and waiter changes during release together as well. Restore the saved mask on every path, including after requesting the switch so PendSV can run.

Verify one contested acquire

Arrange for A to sleep briefly while owning the mutex, and have B call mut_lock() during that interval. Give B a turn after A unlocks. In GDB, observe B blocked with A still owning the mutex, B ready with a free mutex after A's unlock, then B as owner when its original call returns true. Also verify that an uncontended acquire returns immediately.
