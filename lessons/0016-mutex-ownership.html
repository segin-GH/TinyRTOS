Who owns the mutex?

A mutex gives one task at a time permission to use a shared resource. Imagine A and B both call printk(). Each call writes one byte at a time, so a task switch between bytes can mix the two messages. If both tasks take the same mutex around the whole call, its owner has exclusive access until it releases the mutex. FreeRTOS on mutual exclusion

A task can still be preempted while it owns a mutex. TinyRTOS already has a pointer to each task record, so the mutex can remember who owns it even after current_task changes.

First exercise

A acquires a mutex. SysTick switches to B. B calls mutex_unlock() on that mutex. Predict the return value and who owns it afterward.

First implementation

Use a statically allocated mutex and task callers. Start with three operations in src/mutex.c and src/mutex.h.

  • mutex_init() starts the mutex with no owner.
  • mutex_try_lock() records the current task as owner and returns true if the mutex was free. If it already has an owner, return false immediately and preserve the owner. This also covers the owner trying to take it a second time.
  • mutex_unlock() returns true and clears ownership when called by the owner. If the mutex is free or another task owns it, return false and preserve its state.

Make each ownership check and update one uninterrupted operation using the interrupt-mask helpers you already have. Keep that protected section inside the mutex operation. The scheduler can run while the owner uses the shared resource. Add mutex.c to the CMake target.

Check the handoff

Use one mutex with tasks A and B in QEMU. Arrange for A to acquire it and let B run before A releases it. Capture each return value and the owner after A acquires, B tries to acquire, B tries to release, A releases, and B tries to acquire again. A can sleep briefly while holding it to force the test interleaving.
